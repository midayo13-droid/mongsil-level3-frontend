# 몽실 미용실 예약 관리 – 프론트엔드 (Level 3)

**관리자 화면**(사장님·관리사)과 **고객용 화면**(손님, 휴대폰 중심)을 한 사이트에서 **로그인한 역할에 따라** 다르게 보여 줘요.
Next.js로 만들었고 **Vercel**에 올리도록 준비했어요. Level 1 사이트와 데이터는 같지만 화면은 새로 만들었어요.

- **배포된 사이트**: https://mongsil-level3-frontend.vercel.app
- 서버(백엔드) 주소: https://mongsil-level3-backend.onrender.com (저장소 `mongsil-level3-backend`)
- 이 저장소(프론트엔드): `mongsil-level3-frontend`
- 문서: [기획서.md](./기획서.md) · [디자인가이드.md](./디자인가이드.md) · [메뉴구조도_IA.md](./메뉴구조도_IA.md)

> ⏳ 서버(Render 무료)가 잠들어 있으면 **첫 로그인이 1분 가까이 걸릴 수 있어요.** 기다리면 정상으로 열려요.

## 확인용 계정 (가상)

| 역할 | 아이디 | 비밀번호 | 열리는 화면 | 할 수 있는 것 |
|---|---|---|---|---|
| 총관리자(사장님) | `master` | `Master#2026` | 관리자 화면 | 모든 화면 + 삭제·수정·등록 버튼, 관리 메뉴(회원 관리, 관리사 관리, 휴무일 관리, 가상 데이터 다시 채우기), 현황의 **매출** |
| 일반관리자(관리사 **강다은**) | `staff01` | `Staff#2026` | 관리자 화면 | 조회, 고객·강아지 등록·수정, 예약 신청·취소, 미용 기록 등록, 주의사항 추가, AI 도우미(3줄 요약 + 스타일), 현황(매출 제외) |
| 고객 | `customer01` | `Customer#2026` | **고객 화면** | 내 강아지·내 예약만 보기, 강아지 정보 수정·추가, 예약 신청·취소, 내 정보 수정, AI 스타일 추천 |

**회원 관리 화면 확인용 가상 회원:** `member01` – `member05` (비밀번호 모두 `Member#2026`, 보호자 김가은·이준호·박서연·최민재·정유나와 연결된 고객 계정)

**고객은 회원가입도 할 수 있어요.** 로그인 화면의 "회원가입"에서 계정·보호자·강아지 정보를 한 번에 입력해요. 이미 매장에 등록된 휴대폰 번호는 "이미 등록된 번호예요. 매장에 문의해 주세요"라고 안내하고 가입할 수 없어요.

권한이 없는 화면 주소로 들어가면 알맞은 화면으로 되돌려 보내거나 안내를 보여 주고, 서버도 한 번 더 거절해요. (고객은 남의 강아지·남의 예약을 볼 수 없어요.)

## 관리자 화면 (총관리자·일반관리자)

왼쪽 메뉴는 **홈 · 예약관리 · 강아지 · 미용 기록 · 예약 현황 · 공지사항 · 이벤트**예요. "예약 신청"과 "신규 등록"은 각 화면의 버튼으로 들어가요. 사장님에게는 **관리(사장님 전용)** 묶음(관리사 · 휴무일 · 계정 관리 · 가상 데이터)이 더 보이고, 수정·삭제·등록 버튼도 같은 화면에서 사장님에게만 보여요.

| 화면 | 주소 | 내용 |
|---|---|---|
| 홈 | `/` | 맨 위 인사말 카드(예약 신청·신규 등록 버튼), 그 아래 **현황 카드**(오늘 예약 수·이번 달 예약 건수, 사장님은 매출까지), 오늘 예약, 최근 미용 기록, 강아지, 공지·이벤트 |
| 예약 현황 | `/stats` | 위쪽 현황 카드(오늘 예약 수·이번 달 예약 건수, 사장님은 매출까지)를 고르면 아래에 **막대 그래프**(시간대별·날짜별), 달 이동, "표로 보기". 홈의 현황 숫자(건수·원)를 눌러도 와요 |
| 예약관리 - 시간표 (기본) | `/reservations` | 날짜별 관리사 × 30분 시간표. 빈 칸을 눌러 바로 신청 |
| 예약관리 - 목록 (위쪽 선택 상자 "시간표/목록") | `/reservations?view=list` | 검색 + 날짜 범위·상태 필터, **고객이 직접 신청한 예약 표시** |
| 예약 신청 / 상세·취소 | `/reservations/new`, `/reservations/번호` | 규칙에 걸리면 쉬운 안내와 함께 틀린 칸으로 이동. 취소는 예약 당일 00시까지 |
| 강아지 | `/dogs`, `/dogs/번호` | 상세에서 주의사항, 미용 기록, **AI 미용 도우미**(3줄 요약 + 추천 스타일) |
| 신규 등록 | `/register` | 보호자 1명 + 강아지 여러 마리 |
| 미용 기록 | `/records` | 목록·상세·등록 (수정·삭제는 사장님만) |
| 공지사항·이벤트 | `/notices`, `/events` | 사장님만 등록·수정·삭제. 공지는 **첨부파일**(3개까지), 이벤트는 **이미지·링크** |
| 관리(사장님 전용) | `/admin/...` | 메뉴 순서대로 **회원 관리**(가입한 고객 계정 보기·삭제), **관리사 관리**(등록할 때 로그인 계정도 함께 만들기·퇴사 처리·비밀번호 새로 정하기), **휴무일 관리**(공휴일 API 자동 연동), 가상 데이터 다시 채우기 |

관리자 화면의 목록은 **한 쪽에 20건씩** 나뉘고 위쪽에 "총 N건"이 보여요. 고객 화면의 공지사항·이벤트 목록은 아래로 스크롤하면 이어서 불러와요.

## 고객 화면 (휴대폰 중심)

아래쪽 탭 메뉴는 **홈 · 예약 · 내 강아지** 3개예요. **내 정보는 화면 위쪽의 고객 이름("○○님 ›")을 누르면** 열려요. "내 예약"은 메뉴 없이 홈의 "다가오는 예약"과 예약 후 화면에서 들어가요.

| 화면 | 주소 | 내용 |
|---|---|---|
| 회원가입 | `/signup` | 계정 + 보호자 + 강아지(1~5마리)를 한 화면에서 |
| 내 홈 | `/my` | 다가오는 예약, 예약 신청 큰 버튼, 내 강아지, 공지·이벤트 |
| 내 강아지 | `/my/dogs`, `/my/dogs/번호` | 정보 보기·수정, 주의사항(보기만), 미용 이력, **AI 스타일 추천**(추천 스타일만) |
| 강아지 추가·수정 | `/my/dogs/new`, `/my/dogs/번호/edit` | 삭제는 없어요 |
| 예약 | `/my/reserve` | 강아지 → 날짜 → 관리사(**자동 배정** 또는 직접 선택) → 눌러서 고르는 시간 → 스타일. **신청하면 바로 확정** |
| 내 예약 | `/my/reservations` | 다가오는/지난/취소한 예약, 예약 취소(당일 00시까지) |
| 공지사항·이벤트 | `/my/notices`, `/my/events` | 읽기 전용 |
| 내 정보 (위쪽 이름) | `/my/profile` | 보호자 정보 수정, 비밀번호 변경, 로그아웃 |

## 설정값 (환경 변수)

값은 **Vercel 설정 화면이나 `.env.local` 파일에만** 넣어요. `.env.local`은 GitHub에 올라가지 않아요. 예시는 [.env.example](./.env.example)에 있어요.

| 이름 | 뜻 | 예시 |
|---|---|---|
| `NEXT_PUBLIC_API_URL` | 백엔드 서버 주소. 끝에 `/`는 붙이지 않아요 | `https://내-서버주소.onrender.com` |

> `NEXT_PUBLIC_`으로 시작하는 값은 브라우저에서 보일 수 있어요. 그래서 비밀번호·키 같은 값은 절대 넣지 않아요. (서버 주소만 넣어요.)

## 내 컴퓨터에서 실행

먼저 백엔드를 켜 주세요 (기본 http://localhost:4100).

```bash
npm install
cp .env.example .env.local   # 백엔드 주소를 확인해 주세요
npm run dev
```

화면: http://localhost:3100

## Vercel에 올리기

1. Vercel에서 **Add New → Project**를 고르고 이 저장소를 가져와요.
2. Framework는 **Next.js**로 자동 선택돼요. Build/Output 설정은 바꾸지 않아도 돼요.
3. **Environment Variables**에 `NEXT_PUBLIC_API_URL`(Render 서버 주소)을 넣고 **Deploy**를 눌러요.
4. 배포 주소(`https://….vercel.app`)가 나오면, 백엔드 Render의 `CORS_ORIGIN`에 그 주소를 넣고 백엔드를 다시 배포해요.
   (이 값이 맞지 않으면 화면에 "서버에 연결할 수 없어요"가 나와요.)
